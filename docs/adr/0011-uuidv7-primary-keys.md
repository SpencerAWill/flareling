# 0011. UUIDv7 primary keys

- **Status:** Accepted
- **Date:** 2026-10-16

## Context

Every table needs a primary key format, and changing it after data exists means rewriting every foreign key. The candidates:

- **Integer autoincrement:** compact, but it leaks row counts, can't be generated before the insert (so a batch can't reference a row it is creating), and collides when data is merged across databases (a D1 per tenant, for one).
- **UUIDv4 (`crypto.randomUUID()`):** no dependency, but random, so every insert lands on a random page of SQLite's B-tree index. That costs cache locality and page splits as tables grow.
- **Prefixed nanoid (`usr_V1StGXR8...`):** readable, but also random in index order, and not a standard format that tools recognize.
- **UUIDv7 (RFC 9562):** standard, generated in code, and time-ordered, because its leading 48 bits are a millisecond timestamp.

## Decision

We will use UUIDv7, stored as text, for primary keys, generated by `newId()` from `@flareling/db` (backed by the `uuidv7` package, which keeps ids created within one millisecond in order). Tables declare `id: text("id").primaryKey().$defaultFn(newId)`.

UUIDv7 is for primary keys only. Tokens (magic links, sessions, invites, API keys) and public identifiers where creation time shouldn't leak use random values from `crypto.getRandomValues`.

## Consequences

- Inserts append to the index, and ids sort by creation time, which also gives a stable tiebreak for pagination.
- Ids are 36 characters, larger than an integer. That is acceptable at D1's scale.
- A UUIDv7 reveals roughly when its row was created, which is why tokens don't use one.
- The default runs in application code, not SQL, so rows inserted with raw SQL must supply an id.
- Ids that appear in URLs aren't primary keys. Workspaces have a `public_id` from `newPublicId()` (10 random lowercase letters and digits, about 51 bits), and pages live at `/w/<publicId>`. A UUID in the address bar is long, and a UUIDv7 would also show when the workspace was made. Server functions and everything internal keep using the primary key.
