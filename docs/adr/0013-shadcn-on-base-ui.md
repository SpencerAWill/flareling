# 0013. shadcn/ui on Base UI for components

- **Status:** Accepted
- **Date:** 2026-10-16

## Context

`libs/ui` needs accessible primitives for anything beyond a styled native element: dialogs, menus, popovers, comboboxes, tabs. Writing focus management and ARIA behavior by hand is where accessibility bugs come from. The primitive library is hard to change once many components sit on it. The candidates:

- **shadcn/ui on Radix:** what ucmc.spencerwill.com uses, still fully supported. The `radix-ui` meta-package pulls 55 dependencies (individual packages are smaller).
- **shadcn/ui on Base UI:** shadcn's default for new projects since July 2026, from the team behind Radix and Material UI.
- **React Aria Components:** the strongest accessibility behavior, but heavy (about 273 KB gzip for the whole package) and published without npm provenance.

## Decision

We will build `libs/ui` components with shadcn/ui on Base UI (`@base-ui/react`). Components are generated by the shadcn CLI into `libs/ui/src`, owned and edited there, and styled with Tailwind 4. Simple elements that need no behavior (like `Button`, a native `<button>`) stay plain.

Each component gets a story, and with it a Vitest browser test with an axe check.

## Consequences

- Components are source in this repo, so they can be changed freely, and updates from shadcn are pulled deliberately rather than by a version bump.
- Base UI is added to the catalog when the first component that needs it lands.
- shadcn examples written for Radix need adapting; the shadcn docs show both.
